如何阅读：请求方法、参数、版本与缺失信息
  • 同路径的不同 HTTP 方法分开列出，旧版、legacy、TeamBuilder 与 GCloud 路由均保留，不合并计算。
  • GET 通常读取；POST 提交或触发动作；PUT 写入；PATCH 局部修改；DELETE 移除或终止；HEAD 只读取响应头。不能仅凭请求方法保证没有副作用。例如 GET /lol-game-session/v1/clearInfo 可能清理内部状态。
  • 点击接口展开参数与原文列出的响应状态。“未列参数”不等于不需要正文；“200 OK”是文档声明，不是本次调用成功的结果。没有列出的请求体、错误码与响应字段不编造。
  • {id} 等占位符需替换成实际值。accountId、summonerId、PUUID 不应混用。字段类型与必填标记来自源页面；中文参数含义按名称解释。
  • 路径中的 v1、v2 是模块 API 版本，不是游戏补丁版本，不同版本也不自动兼容。实际调用须核对运行中客户端提供的 schema 与状态要求。
  • 俱乐部、旧符文册和旧地区限制等都是本快照的历史模块。客户端接口与游戏内 Live Client Data API、外部推荐站数据、本地 OCR、独立换肤核心不是同一个接口集合。
  • POST /Exit 的原文作用是关闭连接；退出整个应用应另外查看 POST /process-control/v1/process/quit。
  • 本次未连接或调用你的游戏客户端。搜索、主题和复制操作仅在这个文档页面内运行。
