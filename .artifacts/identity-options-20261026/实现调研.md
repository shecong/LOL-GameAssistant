# 身份装饰选项调研

2026-10-26，在当前登录客户端只读核验；没有更改账号装饰。

## 结论

可以补齐边框、挑战勋章、头衔和旗帜的全量目录、预览、所有权标记、应用/回读/恢复。
“目录里存在资源”“isSelectable 为 true”“接口接受提交”“实际装备并持续显示”是不同证据。
目前不能证明未拥有的项目能够跨所有类别装备，也不能用本地显示替换表示账号获得了项目。

## 当前客户端实测

- GET `/lol-game-data/assets/v1/regalia.json`：200，140 条装饰资源定义。
- GET `/lol-regalia/v3/inventory/REGALIA_BANNER`：200，38 个组，6 个 isOwned=true、32 个 false。
  未拥有的旗帜也存在 isSelectable=true，因此两个字段不能互相替代。
- GET `/lol-challenges/v2/titles/all`：200，358 条；
  GET `/lol-challenges/v2/titles/local-player`：200，95 条本人头衔。
- GET `/lol-regalia/v2/current-summoner/regalia`：支持 preferredCrestType、preferredBannerType、selectedPrestigeCrest。
- POST `/lol-challenges/v1/update-player-preferences` 是勋章 challengeIds、头衔 title、旗帜 bannerAccent 的候选写入入口；本轮未发送写请求。

## 现有项目缺口

- `LcuClientRegaliaService` 仅切换实际段位/等级类型，保留 selectedPrestigeCrest；没有选择任意等级边框。
- `LcuClientFeatureService.ClearChallengeBadgesAsync` 仅提交空 challengeIds；没有完整勋章、头衔、旗帜编辑器。
- 新增编辑器需要完整保留其他偏好与可恢复原始值，并验证账号/大区，避免改一项重置其他项。

## 后续实测必须分别记录

选中的全量目录 ID、原始所有权、提交状态、应用后回读、界面显示、重新读取后的保持情况与原样恢复。
