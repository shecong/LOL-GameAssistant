# 文件换肤运行组件

运行时使用本目录的 `mod-tools.exe`、`cslol-dll.dll` 和 `hashes.game.txt`，通过外部进程执行 import / mkoverlay / runoverlay。其他三个工具只用于资源制作。

从仓库根目录执行 `./tools/prepare-cslol-resources.ps1 -SourceResources 'C:\app\PLskin\resources'`，准备本机集成文档所指的资源。脚本生成工具 SHA256 清单；大文件不进入 Git。构建和发布会把已准备资源复制到输出目录。

上游项目：[LeagueToolkit/cslol-manager](https://github.com/LeagueToolkit/cslol-manager)。本项目没有修改工具二进制。此处是本机已有组件的集成入口，公开发行这些组件前应核对所用版本的许可证和分发条件。

## 无盘 / 虚拟盘 IO 兼容

导入皮肤或生成覆盖层时，如果工具报告无法打开游戏 WAD、无法建立游戏索引，即使退出码为 0，助手也不会接受不完整索引。助手会尝试用普通文件流将 `Game/DATA/FINAL` 下的完整 `.wad.client` 文件复制到 `%LOCALAPPDATA%/LOL-GameAssistant/Cslol/game-index-mirrors`，使用该镜像重试一次。之后的导入和覆盖层生成沿用镜像；`runoverlay` 始终使用真实游戏路径。

当前工具生成覆盖层还需要读取原始资源内容，因此镜像包含完整 WAD，不是仅复制索引头。首次回退会检查剩余空间并显示复制进度，所需空间接近游戏 WAD 总大小。正常读取成功不会建立镜像。仅复制 WAD，不复制游戏可执行文件或 DLL，不修改安装的 WAD。

镜像按游戏路径、可执行文件和 WAD 文件列表的大小及修改时间区分。复用前校验每个缓存 WAD 的 SHA256；游戏更新或删除资源后重新建立对应快照。复制期间检测到资源变化、读取拒绝、空间不足或取消操作时，不发布半成品。旧快照保留，关闭助手后可删除整个镜像缓存目录释放空间，下次需要时重新建立。

兼容目标是原卷的文件映射等 IO 行为异常，但普通文件流仍能读取资源的环境。如果普通文件读取本身也被拒绝，助手会明确报错并提示检查权限或联系网吧管理员。此机制不改变进程加载通道，也没有针对玄武、磐石等驱动级安全软件的绕过能力。自动化测试不能替代实际网吧环境验收。
