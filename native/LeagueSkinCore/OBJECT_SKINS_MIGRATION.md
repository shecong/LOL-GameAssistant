# 原版一小兵、眼位逻辑移植记录

日期：2026-10-11。目标项目：weather-app。状态：已完成当前对象的手动换肤与恢复，已完成本轮游戏验证；不代表全部主题、眼位条目或地图通过验收。

## 本轮交付

- 游戏换肤页新增“小兵与眼位”卡片：读取、选择、应用、恢复。
- 小兵主题按原版一的成对编号规则选择：本地阵营 1 使用 `2 × 索引`，阵营 2 使用 `2 × 索引 + 1`。界面提供原参考实现的 11 个主题。
- 眼位名称通过当前游戏 `game_character_skin_displayname_SightWard_<编号>` 翻译键读取。扫描 0..1000，保留已翻译且非空的条目，当前返回 266 项；不假定编号连续。
- 普通眼位模型允许 YellowTrinket、BlueTrinket、SightWard、VisionWard、JammerDevice。当前版本的归属包装对象首字段必须对应本地英雄，才允许修改。
- 英雄与对象请求共用串行队列；每次应用前重新读取目录、核对会话与原皮基线。不存在的目标、混合且尚未捕获原皮的编号、非法选择、未知版本均停止调用。
- “恢复对象原皮”使用本次会话首次捕获的原编号；“恢复并停用”先恢复已修改的对象，再恢复英雄，最后停用。
- 关闭普通开关仍只停止新请求。原皮基线保存在当前程序会话内；本轮没有实现持久化的跨程序重启恢复。
- 2026-10-11 版本仅应用已有对象；2026-10-16 已增加本局后台同步：应用核验成功后每 2 秒重新扫描，并按最后应用的主题刷新新生成对象，切换页面不影响同步。恢复对象原皮、停用、会话失效时停止；后台同步失败或结果不确定时停止并记录 `object_maintenance_stopped`，不自动重试。没有目标的空档继续等待，不覆盖首次原皮基线。
- 2026-10-16 回归：SkinCoreServiceTests 44 项、SkinToolsTests 20 项通过，覆盖新波次、零目标后重新出现、切换主题、恢复排队、会话/版本变化与不确定结果停止。新增后台同步尚未进行游戏内画面验证；上文游戏验收记录仅对应 2026-10-11 版本。

## 原版证据与当前版本差异

原版文件：`E:\tools\output\lol-assistant-analysis\downloaded-dlls\R3nzSkin.dll`，SHA256 `87d29e8391c7492251c4df857a7e177720f901feb6c84d4bf156c0a9f748534d`。原版对象循环、编号规则、模型哈希和尾部基础编号清零记录在同目录 `minion-ward-loop.asm` 和 `minion-ward-camera-evidence.json`。

当前游戏必须匹配既有 GameProfileSha `d8e14b858178774e512635c7974c3d9b9fbee6d96ab0576e89ef4fa5b32ecb39`，以及新增对象适配指纹。名单槽为 RVA `0x1eec800`，名单指针位于管理器 `+8`，数量位于 `+0x10`；数量、页可读性和皮肤层均检查边界。

实测旧虚表槽 F0 的返回值对应野怪标记，不能继续称为当前版本的小兵判定。移植版本采用八个明确的召唤师峡谷兵线模型名称允许名单，避免修改野怪、英雄及其他临时对象。不覆盖未经验证的地图模型。

本地阵营字段使用当前实测 `+0x239`。原版一的 `+0x251` 在这局读取为 0，不能直接复制。

眼位归属候选入口 RVA `0x29f530` 跳转到 `0x2230b0`。当前对象 `+0x6f8` 读到的是包装指针，不能直接与本地英雄地址比较；本轮放置的眼位包装首字段对应本地英雄。此轮尚未包含敌方眼位的游戏内反例测试，不能把单局观察写成全部归属场景已验收。

对象仍通过已确认的 CharacterDataStack、相同模型皮肤层同步与游戏 Update(true) 刷新。没有执行原版尾部强制基础编号清零。测试发现游戏会在请求之间回写基础编号，而画面资源仍可保留上次选择；因此手动应用、恢复均强制刷新，即使采样编号已等于目标编号。

接口状态核验只覆盖皮肤层与模型状态，不替代画面验收。不强行卸载游戏模块，没有新增反检测或检测绕过。
