# 独立核心运行时适配

2026-10-29。此改动解决的是固定版本实现与原版运行时定位之间的机制差异。此前补发发布文件仅解决部署遗漏，不能解决下一个游戏版本的定位问题。

## 根因与改动

原版1有两层机制：前端通过授权接口取得远端功能 DLL；DLL 内又在运行时扫描指令特征，通过 RIP 相对引用、相对调用和指令位移确定地址，并包含兼容分支。相同前端 EXE 能继续使用，不代表同一份功能 DLL 永久兼容：本次下载模块的长度和 SHA256 已与 10 月 9 日样本不同，属于远端功能载荷更新。

此前独立核心既不下载这份远端 DLL，又把一次分析得到的 RVA/全局槽写成常量，`independentImage` 还要求时间戳、映像大小、13 处完整字节全部匹配。重新编译不会改变这些常量；因此游戏更新后仍会在校验阶段退出。

现在英雄换肤入口始终使用 `runtime_profile.h`，不以旧时间戳、映像大小或旧 RVA 决定是否兼容。`game_profile.h` 留作历史参考和其他尚未迁移的功能校验，不再给英雄换肤提供最终执行地址。

核心直接读取游戏自身的可执行节，使用本地编译的特征库查找玩家、英雄数据库、皮肤栈、编码/解码及刷新函数。相对地址、分支位移和明确需要解析的对象字段位移允许变化；操作码、编码常量和层栈布局仍保留约束。匹配后计算真实目标，并检查唯一性、内存边界、目标区域、两处翻译调用一致性、Push 调用与函数体一致性、编码和解码字段一致性；之后仍执行原有对象、目录、会话和写后读回校验。

英雄、小兵/眼位、相机配置、实际镜头按组定位。相机或对象定位失败不会阻止英雄功能初始化。段位框仍有独立的已知版本布局限制，不因英雄定位成功而放开未知版本的写入。

这些操作不调用原版程序、不下载原版模块、不使用授权 SDK，也不需要原版进程运行。标准与混合构建共用同一解析器；没有新增或加载驱动。

## 缓存与诊断

助手保持一个 16 KiB 匿名共享内存缓存，保存定位 RVA 和规则索引。缓存按游戏 PID、进程创建时间、时间戳、映像大小及规则指纹区分；缓存数据有完整性检查，使用前仍核对实际指令并重新计算相对目标和布局。缓存不保存函数指针、账号或认证数据；它是性能优化，失效或不可用时重新扫描。所有共享内存操作不等待其他请求持锁。

`profile` 是只读诊断命令，返回实际解析地址、规则指纹、`profile_resolution.mode=runtime_signatures`、`cache_hit` 和定位耗时。失败会区分：

|错误|含义|
|---|---|
|`profile_signature_missing`|具体定位规则未命中，stage 指出如 `locator:skin_decode`|
|`profile_signature_ambiguous`|出现多个候选，不选第一个继续执行|
|`profile_schema_not_verified`|目标或字段之间的语义关系不通过|
|`profile_code_not_ready`|代码页尚不可读，不更改页面保护来强行读取|

诊断结构也进入助手的失败日志；UI 提示具体为定位、歧义、布局或代码尚未就绪，而不是把所有情况统称为版本过期。

## 之后怎样适配游戏更新

1. 直接运行同一核心。只要已支持的指令/布局家族仍成立，核心自行重新定位，无需修改版本号或重新编译。
2. 出现不兼容变化时，运行 `league-skin-core-host.exe profile` 查看具体失败规则。`tools/verify-skin-auto-runtime.ps1` 默认只读地检查当前实际解析和缓存；显式传入 `-TestSkin` 才会临时切换并尝试恢复精确原值。
3. 如需代码参考，运行 `tools/prepare-skin-update-probe.py`，编译生成的 `tmp/skin-update-probe/build.ps1`，然后使用 `tools/capture-skin-update-via-bridge.py` 采集可执行节。这个受限探测构建只接受状态与代码分页请求，不包含可触发的换肤命令；系统拒绝读取时停止。全程不需要原版1。
4. 依据游戏自己的新代码更新本地参考和规则，再运行 `tools/generate-skin-runtime-patterns.py`、原生测试及真实读回验证。规则编译进核心，最终运行不依赖 Python、Capstone、原版 DLL 或网络服务。

不能承诺任何未来版本永久兼容。函数重写、编码算法、层栈 ABI 或特殊皮肤语义发生变化时需要维护独立规则或实现。此次自动解析支持地址移动及受约束的字段位移变化，不是忽略版本检查后猜测地址。特殊皮肤规则表与段位框等独立功能也不等于所有未来内容会自动恢复。

## 验证证据

- 同一解析器通过 10 月 22 日、10 月 29 日两份本地参考指令测试。
- 通过合成更新测试：时间戳和映像大小改变，代码地址整体移动、全局槽另行移动、皮肤栈从 `0x3638` 变为 `0x3700`、编码字段从 `0xbe4` 变为 `0xc00`，仍解析到新结果；这是模拟测试，不是声称未来游戏版本已经实测。
- 拒绝多候选、缺失指令、解码器变化、非法相对目标及不可读页；测试缓存损坏、进程创建时间不符、构建不符和实际代码变化时不使用缓存。对象/相机失败不阻止英雄定位。
- 保存的完整游戏代码快照直接交给 C++ 解析器验证通过；该过程不运行快照内的代码。
- 原生测试及跨版本/缓存测试通过，相关服务测试 89 项、相关 UI 测试 45 项通过；主程序 Release 构建 0 警告、0 错误。
- 实际对局为 `KIWI / Map12`，英雄 Singed，原版1进程数为 0。自动定位后 5 → 0 → 1.2 秒独立读回 0 → 恢复 5 → 独立读回 5，通过；当前已恢复原值。首次解析 156 毫秒，缓存命中后的解析耗时为 0 毫秒（GetTickCount64 粒度，不代表整个请求零耗时）。
- 当前对象目录及相机配置读取通过，本轮未写入小兵/眼位或镜头；换肤画面、技能表现及长期稳定性仍待用户确认。混合模式完成编译和用户态协议测试，没有加载驱动进行游戏运行时验收。
