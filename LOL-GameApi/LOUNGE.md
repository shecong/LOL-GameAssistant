# lol休息室

单实例 ASP.NET Core SignalR + SQLite 公共聊天室。菜单在“关于”前面；后台连接不依赖打开页面。

## 本机运行

```powershell
dotnet run --project LOL-GameApi --no-launch-profile --urls http://127.0.0.1:5088
```

在助手“lol休息室”填写 `http://127.0.0.1:5088` 并保存连接。未登录 LOL 可以阅读；登录后使用当前玩家身份发言。测试跨用户广播需两台助手，或使用后端集成测试中的两个 SignalR 客户端。

## 公网部署

1. 发布 `LOL-GameApi` 到安装了 **ASP.NET Core 10.0.13 或更高补丁版本**的主机。
2. 客户端支持 HTTP 和 HTTPS。直接运行 EXE 时可使用 `LOL-GameApi.exe --urls "http://0.0.0.0:5000"`，并放行云平台及 Windows 防火墙的 TCP 5000；客户端填写 `http://服务器公网IP:5000`。HTTP 会明文传输消息与安装会话凭据。使用 HTTPS 反向代理时，启用 WebSocket Upgrade，代理空闲超时至少 90 秒，后端可监听回环地址。
3. 保留 `/hubs/lounge` 和 `/hubs/lounge/negotiate` 路径及 Authorization 请求头。客户端不放宽证书校验。
4. 数据库默认位于后端内容目录 `data/lounge.db`；挂载持久化目录并给进程写入权限。SQLite WAL 备份请使用在线备份或停服务后同时处理数据库及 WAL 文件，不要只复制活跃的主数据库文件。
5. 助手内置默认服务器 `http://159.75.148.241:5000`。用户自己的配置优先；未配置时使用 `LOL_LOUNGE_SERVER` 环境变量或主程序旁的 `lounge-server.txt`，最后回退到内置地址。文件中只写服务器根 URL。所有客户端指向同一实例即可自动加入公共频道。

不包含公网发布和域名配置。客户端配置和受当前 Windows 用户 DPAPI 保护的随机安装凭据存于 `%LOCALAPPDATA%/LOL-GameAssistant/lounge.json`。LCU 密钥和 Riot 登录凭据不会上传。

## 规则与管理

- 纯文本，最多 500 字，每个安装会话每 2 秒一条。初次读取最近 100 条，重连按编号补齐，界面最多保留 300 条。
- 在线状态每 5 秒校准；45 秒没有更新时失效。按玩家及平台合并多连接，未知身份按安装会话区分。退出或换号不沿用缓存身份。
- 登录玩家连接频道后自动播报上线，同账号多开或 10 分钟内重连不会重复播报。上线文案与在线成员列表显示已取得的单双排及灵活段位；无段位时不编造。段位每分钟刷新。在线列表支持右键复制名称、编号（`#` 后缀）、完整游戏 ID、频道标识；Ctrl+C 复制完整游戏 ID。
- 胜局文案示例：`🎉 【小明#123】（艾欧尼亚）与【小红#456】组队开黑，拿下了一场【单双排】胜利！漂亮，下一把继续！`。开黑成员只来自本次观察到的大厅组队快照，并与精确对局结算的同队名单交叉核对；没有可靠记录时只播报胜利。客户端与服务端均需更新才能使用新增播报字段。
- LOL 离线状态或关闭“公开游戏状态与胜局”时隐藏活动并停止播报。“显示胜局播报”只影响本机显示，修改公开设置后点击“保存并连接”。
- 只播报启动后实际观察到进行中的常见队列胜局，结算最长重试 3 分钟，短暂聊天断线后可补报，超过 10 分钟丢弃。不补发助手关闭期间的历史胜局。重开、自定义、训练、人机及尚未支持的排名制模式不播报。
- 大区优先读取 LCU 平台配置，缺失时查询当前账号实时战绩响应的顶层平台元数据，再降级区域信息；无法识别显示未知，禁止猜测。国服合区或客户端版本导致的平台差异需真实环境核验。
- 消息默认保留 7 天，在数据库读写时清理；胜局去重记录保留 30 天。`Lounge:RetentionDays` 可设置 1–90 天。客户端消息重试在记录保留期内去重。
- `Lounge:MutedSessions` / `BannedSessions` 配置安装会话 SHA256 标识，服务日志会记录连接会话。配置文件重载后，禁言立即拦截发送；封禁拦截后续调用及连接。管理员应保护日志，不公开这些标识。
- 设置环境变量 `Lounge__AdminKey` 为至少 32 字符随机值后，可通过 `DELETE /api/lounge/messages/{id}` 删除消息，请求头使用 `X-Lounge-Admin-Key`。密钥只保存在服务端。删除事件会推送，历史查询返回删除占位。
- 在消息上右键可本地屏蔽该发送者；页面提供清空屏蔽名单。
- 反向代理还应对连接入口按真实来源 IP 限流。应用不会无条件信任客户端提交的 X-Forwarded-For；代理场景的应用 IP 限额会共享，可通过 `Lounge:MaxConnectionsPerIp` 调整连接配额（默认 100），并在反向代理设置真实 IP 限流。

## 招募、提及与表情包

- 发送框上方“开黑招募”可选择大区、模式、段位要求、缺少位置和人数，填写最多 120 字补充说明，发布到公共频道。发布使用独立 `PublishRecruitment` 接口，需要客户端和服务端均更新到协议 v3（健康检查 `/api/health` 的 `loungeProtocolVersion` 为 3）。旧服务端会明确提示升级，禁止将空文字招募发往旧接口；协议 v2 的表情及提及仍可使用。
- 点击“招募列表”，或双击/右键频道里的招募打开详情。同大区登录玩家可以报名，占用一个缺少名额；重复报名不重复计数，退出立即释放名额，已满员时不能再加入。发起人可查看报名玩家、结束招募；其他玩家不能结束。招募发布后 30 分钟过期，满员、结束、过期状态会显示在频道、列表和详情中。段位和位置为招募要求，由双方确认，不自动认证或分配位置。
- 报名成功后可复制发起人完整游戏 ID，在 LOL 客户端添加好友组队；报名不自动加入游戏大厅。发起人收到新报名提醒，受免打扰和游戏中静音设置控制。右键消息也可复制 ID 或提及在线发起人。
- 招募及报名存于自动创建的 `recruitments` 表，沿用原数据库，无需重建。容量检查和写入串行执行，避免多人争抢时超额；重试、退出及结束操作幂等。实时状态带递增版本，重连通过完整招募快照补齐状态更新，数据库重启保留报名，删除消息后禁止操作招募。原协议 v2 历史招募仅作文字展示，需重新发布才能管理报名。
- 使用“@成员”或在线成员右键菜单选择目标；每条消息最多提及 5 人。目标通过稳定的频道玩家标识匹配，不依赖同名昵称。直接手打名字不会产生定向提醒。
- 在线列表右键“关注上线提醒”保存关注，星标标记已关注成员；再次右键可以取消。初次进入和恢复连接时不把同步到的全部在线成员当成新上线。
- “免打扰”关闭频道弹窗提醒；“游戏中静音”在对局中抑制提醒，保留未读，结束后提示未读及提及数量。未读计数也显示在休息室标签；打开并聚焦频道会标为已读，也可点击“标为已读”。历史初次同步、自己的消息、屏蔽成员和已处理过的重放不会增加未读。
- “表情包”提供 8 个内置图片，选择后需点击“发送”。协议只传预设编号，由客户端绘制内置表情；服务端只接受白名单编号。不提供上传、拖入或粘贴图片发送；自定义图片、图片 URL、base64 等不能作为表情包发送，聊天区不加载远程图片。
- 五杀、超神、晋级提供独立自动播报开关，同时受“公开游戏状态与战绩”控制。五杀来自精确对局本人 `pentaKills`；超神要求本人 `largestKillingSpree >= 8`，不按总击杀数猜测。晋级仅比较观察到的单双排/灵活对局前后同队列段位层级，不把胜点上涨算作晋级；结算后最多等待 3 分钟的新段位。重开、自定义、未支持模式、缺失数据和未知初始段位不会猜测播报。
- 招募、提及、表情和精彩战绩均持久化到现有消息表。精彩战绩按玩家、对局、类型去重，并沿用胜局去重表保存 30 天；无需重建数据库。新类型需要同时更新服务端与客户端，旧客户端只能看到部分原始内容。

## 信任边界

这是匿名安装会话认证，不是 Riot 官方账号认证。昵称、大区、PUUID 和胜局均来自用户本机 LCU 上报；服务端核对当前身份、队列、时效并去重，但修改过的客户端仍可伪造资料和结果，重置安装凭据也可规避基于安装的禁言。消息不应标注为“官方验证战绩”，也不能据此发放奖励。更强的账号认证和服务端战绩核验需另行接入。

当前仅支持一个服务实例。多实例部署需要共享在线状态、消息广播和去重存储；不能简单在负载均衡后复制实例。


自动化覆盖真实 SignalR 连接、凭据校验、多人广播、在线合并、禁言、发送限流、胜局去重及 SQLite 重启保留。LOL 在线/结算端点及大区仍需运行真实客户端验收。
