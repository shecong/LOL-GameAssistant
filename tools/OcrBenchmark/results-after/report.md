# 修改后的生产 OCR 验证

2026-10-07，直接编译并调用生产 AugmentImageRecognizer，使用原始四张用户截图及相同人工标注的客户区。与第一次探索相同的样本，非独立验证集。

| 截图 | 类型 | 正确名称 | 三张卡片总耗时 |
|---|---|---:|---:|
| image1 | 黄金 | 3/3 | 81.2 ms |
| image2 | 黄金 | 3/3 | 46.6 ms |
| image3 | 棱彩 | 3/3 | 77.4 ms |
| image4 | 棱彩 | 3/3 | 675.3 ms |

合计 12/12，平均 73.4 ms/卡。复测中的原宽区域流程平均 214.6 ms/卡，两者使用相同的修改后匹配器。计时包含图像识别及匹配，不含引擎初始化、窗口截屏及后续推荐操作。image4 的“夺金”仍需模糊匹配和宽区域回退，因此耗时较高。

生产流程比前一轮探索组合更保守：只有名称完全匹配才提前结束；模糊结果继续执行原宽区域扫描，短名称模糊匹配至少需要两次 OCR 支持。因此不能把探索组合的约 22 ms/卡当作最终生产耗时。

原有误识别已被阻止：10% 宽度实验中的“残忍→扇巴掌”和“急急小子→巫师式思考”现在均返回未确认。误识别转为漏识别是预期行为，生产的回退流程继续寻找有效标题。

匹配器增加语言过滤；短拉丁片段不模糊匹配；拉丁跨行拼接要求每个片段至少三个字符；子串匹配要求足够长度和覆盖比例；两到三字中文名称不接受单字替换，但保留单字插入/删除容错。四字及以上模糊相似度门槛为 0.75。

新增 4 项回归用例，名称匹配相关 16 项通过；完整单元测试 149 项通过；主程序编译零警告、零错误。模型复用由扫描器串行化保护，取消排队或扫描时释放锁。真实游戏窗口、多种 UI 缩放和白银卡片尚未验证。
